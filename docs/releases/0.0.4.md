# Captura 0.0.4

Historical release record: the auxiliary reader described below was removed
in the corrected 0.0.5 debug build. Preview and editing now use centered
overlays inside the existing menubar panel; see `0.0.5.md`.

The capture reader opens in a reusable auxiliary window. Double-click previews;
the pencil and Edit shortcut open the source immediately. Wide windows show source
and rendered Markdown together; narrower windows use tabs. The queue keeps its
430 px layout and displays a bounded Markdown excerpt.

Drafts require Save, Discard, or Cancel before navigation or closing. SQLite
compares the saved timestamp before accepting an edit. A stale edit or failed save
keeps its draft. Capture events carry revisions; both windows reject older data.

Section menus use 168 px width and 28 px action rows. Confirmation expands to
200 px and explains that captures move to Unfiled. Both states stay inside the
window and contain keyboard focus.

Validation: 64 frontend tests, 23 Rust tests, Clippy with warnings denied, and
production/Tauri builds passed. The signed package passed strict verification.
Actual WKWebView checks confirmed preview/edit layout, dirty Cancel, exact-source
save, stale-save draft retention, Discard, reader clearing, and measured menu
dimensions. These checks used programmatic DOM actions. Native interaction latency
and the narrow-window layout were not measured in this release pass.
The local app and DMG are signed with Captura Dev and are not notarized.
Evidence: `output/verification/release-0.0.4.json`, `output/qa004/`.

No updater feed, GitHub release, or remote push is included.
