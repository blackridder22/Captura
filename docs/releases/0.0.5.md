# Captura 0.0.5

Add image opens Choose images or Paste image. All image entry points use one
bounded background service, including the clipboard shortcut and copied selection.
Finder file URLs and image pixels are accepted without downloading remote URLs.

PNG, JPEG, TIFF, HEIC, WebP, GIF, and BMP are validated using file signatures and
ImageIO metadata. Imports preserve oriented full-resolution PNG originals and
create 480 px queue thumbnails. Animated/multipage inputs report first-frame use.
Limits: 20 files, 200 MiB per batch, 50 MiB per input, 40 MP, and 16,384 px per edge.

The selected section is fixed at import start. Deleted sections fall back to
Unfiled with a warning. Successful files retain input order; failed files have
individual messages. Files are staged and database errors remove uncommitted
attachments. Older captures receive thumbnails when visible.

Validation and native evidence are recorded in `output/verification/` and
`output/qa005/`. No remote release or updater-feed change is included.

78 frontend tests and 48 Rust tests passed (two measurement benchmarks ignored),
with strict TypeScript, production frontend build, all-target Clippy, Tauri
packaging, strict code-sign verification, and an isolated packaged launch.
Packaged WKWebView/IPC checks verified all seven formats, orientation, full
originals and thumbnails, section/order persistence, partial failures, native
clipboard file-URL inputs, and visible batch-limit errors. Native NSOpenPanel
cancellation returned an empty cancelled result. Exact picker selection using
automated physical keystrokes remains unverified: it selected a different file.
Real Finder Command-C and native interaction latency remain unverified.
The isolated smoke mode skips global shortcut registration.

The signed local artifact is `output/releases/0.0.5/Captura_0.0.5_aarch64.dmg`.
It is not notarized or published.

After drag-and-drop was canceled, the remaining file-drop listener, overlay,
and unused file-path import command were removed. Native webview file-drop
handlers are disabled. Image entry points are Choose images, Paste image,
and the existing clipboard shortcuts. The abandoned 0.0.6 source archive and
native drag test helpers were deleted. File-based codec QA uses the existing
opt-in isolated QA channel; it is not an application command.

The corrected local debug build keeps preview and editing inside Captura's
existing menubar panel. Double-click opens a centered, read-only Markdown
overlay with the complete scrollable text. The pencil opens a centered editor
with Source and Preview tabs. Closing returns to the same queue position;
unsaved drafts and failed saves are retained. Queue controls are inert while
an overlay is open.

The auxiliary reader window, its request/close commands, browser popup route,
capability, and duplicate editor components were removed. Packaged WKWebView
checks verified both overlays at 430 by 650 and 430 by 520, with zero horizontal
or vertical centering error. Only `main` and the existing `capture-hud` webviews
exist before and after opening both views. Checks use programmatic DOM events,
not physical pointer input. Evidence and screenshots are in
`output/qa-centered-overlays/`; the corrected debug app and DMG are in
`output/debug/0.0.5-centered-overlays/`.
