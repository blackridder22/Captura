# Performance and native verification

Measurements must distinguish component rendering from packaged WKWebView and
cross-application native behavior. Passing a unit test or compiling an AppKit
bridge does not establish a real drag session.

## Reproduction

- `pnpm test` and `pnpm build`
- `cargo test --offline --manifest-path src-tauri/Cargo.toml`
- `cargo clippy --offline --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings`
- `pnpm tauri build`, strict code-sign verification, isolated packaged launch
- `node script/benchmark-markdown.cjs e96b511` for the old queue renderer
- `node script/benchmark-markdown.cjs` for the bounded queue renderer

The Markdown script uses production Node SSR, 3 warmups and 30 measured samples
at 1, 10, and 100 KiB. It is not a native interaction-latency benchmark. Full source
remains available in the reader; only the queue input is capped at 1024 Unicode
characters. Concurrent build activity affects absolute timings.

Packaged QA is opt-in: `CAPTURA_TEST_MODE=1`, an absolute `CAPTURA_DATA_DIR`, and an
absolute `CAPTURA_QA_DIR`. `script/qa.py` reads JSON actions on stdin. This isolated
mode skips global shortcut registration, grants asset access only to its temporary
attachments directory, and leaves the normal Captura database alone. Normal
launches create no QA polling thread or request directory.

Required native targets: warm panel p95 <=150 ms; 10 KiB detail p95 <=250 ms;
10 KiB typing-to-paint p95 <=50 ms; drop feedback p95 <=100 ms. Unmeasured targets
must be reported as unverified.
